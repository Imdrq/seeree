# Seeree 联网搜索功能 — 实现方案

## 背景

为 Seeree 语音助手添加联网搜索能力。参考调研文档 `Seeree_联网搜索方案调研与架构建议.txt`。

**核心原则（文档 §13）：**
1. Search 是 Tool，不是 LLM Provider 的内置功能
2. Provider 是可替换实现（统一接口）
3. API Key 只存在 Electron Main
4. 搜索结果必须结构化
5. Search 与 Research 分离
6. 搜索与 LLM Provider 解耦

## 架构

```
用户语音 → Vosk ASR → 文本
                ↓
        ① 搜索意图检测（关键词/规则）
                ↓ 需要搜索
        ② SearchManager → WebSearchProvider.search()
                ↓
        ③ 结果标准化（去重/排序/截断/保留来源）
                ↓
        ④ 注入 prompt → LLM 总结回答（附来源 [1][2][3]）
                ↓
        ⑤ TTS 播报 + 字幕
```

**Electron 安全边界（文档 §8）：**
```
React Renderer → IPC → Electron Main → WebSearchProvider → Internet
```
API Key 只在 Main 进程，渲染层不直连网络。

## 文件结构（文档 §9）

```
src/services/search/
  SearchTypes.ts          # SearchRequest / SearchResult / SearchResponse
  WebSearchProvider.ts    # 统一接口定义
  SearchManager.ts        # Provider 选择、去重、标准化、配额
  providers/
    TavilySearchProvider.ts   # V1 实现（最快上线）
    BraveSearchProvider.ts    # V1.5 云端备用
    SearXNGSearchProvider.ts  # V2 自托管首选
electron/services/search/
  WebSearchService.ts     # 主进程搜索服务（IPC handler）
```

## 第一版 Provider 选择

文档建议：**最快上线 → Tavily**，**长期自主 → SearXNG**。

V1 实现 **TavilySearchProvider**（1000 次/月免费，专为 AI 设计，返回干净摘要），
V1.5 加 **BraveSearchProvider**（2000 次/月，独立索引）。
SearXNG 留给 V2（需要用户自己部署）。

## 实现细节

### 1. 类型定义 (SearchTypes.ts)

```typescript
interface SearchRequest {
  query: string
  maxResults?: number        // 默认 5
  language?: string          // 默认 'zh'
  timeRange?: string         // 'day' | 'week' | 'month'
}

interface SearchResult {
  title: string
  url: string
  snippet: string
  content?: string           // 网页正文摘要
  publishedAt?: string
  source?: string            // 域名
  score?: number             // 相关性评分
}

interface SearchResponse {
  ok: boolean
  results: SearchResult[]
  quotaRemaining?: number
  message?: string
}
```

### 2. Provider 接口 (WebSearchProvider.ts)

```typescript
interface WebSearchProvider {
  name: string
  search(request: SearchRequest): Promise<SearchResponse>
}
```

### 3. TavilySearchProvider

```typescript
// POST https://api.tavily.com/search
// Body: { api_key, query, max_results, search_depth, include_answer }
// Response: { results: [{ title, url, content, score }] }
```

### 4. SearchManager

- Provider 选择（配置指定）
- 结果标准化：URL 归一化、去重、按 score 排序、截断（每条 ≤ 500 字符，总数 ≤ 5 条）
- 保留来源信息（title/url/source）供 UI 显示 `[1][2][3]`
- 配额计数（按自然月，写入 `%APPDATA%/Seeree/search-quota.json`）

### 5. IPC (main.ts)

```
search:web  → SearchManager.search(request) → SearchResponse
search:quota → { used, limit, month, warning }
```

### 6. 配置字段 (useAIConfig.ts)

```typescript
interface SearchConfig {
  enabled: boolean
  provider: 'tavily' | 'brave' | 'searxng'
  apiKey: string             // 走 safeStorage 加密
  quotaLimit: number         // 默认 1000（Tavily）或 2000（Brave）
  quotaUsed: number
  quotaMonth: string         // "2026-10"
  warnThreshold: number      // 默认 5
}
```

### 7. 搜索意图检测 (GlassBubble.tsx)

文档 §11 的触发条件：
1. 用户明确要求"搜索/查一下/网上找"
2. 问题依赖实时信息（今天新闻、最新版本、当前价格、赛事）
3. 本地模型知识可能过时
4. 用户要求来源或链接

```typescript
const SEARCH_TRIGGERS = [
  '搜索', '搜一下', '查一下', '查查', '帮我搜', '帮我查',
  '最新', '新闻', '今天', '天气', '股价', '比赛', '实时',
]
```

### 8. 结果注入 prompt

```
以下是网络搜索结果（请据此回答并标注来源编号）：
[1] 标题 | 来源域名 | 摘要片段
[2] 标题 | 来源域名 | 摘要片段
...
```

### 9. 联网设置页 (ControlPanel NetworkSection)

- **搜索开关**：启用/禁用
- **Provider 选择**：Tavily / Brave / SearXNG（SearXNG 显示"需自行部署"）
- **API Key**：输入框（加密存储）
- **本月用量**：进度条（已用/剩余）
- **剩 N 次警告**：黄色提示（可调阈值，默认 5）
- **用完降级**：不搜索，LLM 直接回答并说明
- **请求超时**：可调（默认 5s）

7. 用完 → 自动降级提示
8. 跨月自动重置
